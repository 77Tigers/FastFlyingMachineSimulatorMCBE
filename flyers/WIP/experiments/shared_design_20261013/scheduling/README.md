# Prescribed-event scheduling, 2026-10-13

The explicit `interleaved` mode inserts supplied events between natural piston
visits and varies the order of multiple supplied inputs. The two legacy batch
modes retain their behavior. This is synthetic stress scheduling; prescribed
settlement remains after the power snapshot and before natural updates. No
concrete driver or universal update-order guarantee is inferred.

## Reproduction and finite evidence

From the repository root:

```powershell
cargo build --release --manifest-path tools/Cargo.toml --target-dir target --bin extension-prescribe --bin contract-search
python -B flyers/WIP/experiments/shared_design_20261013/scheduling/verify.py
cargo test --lib
cargo test --manifest-path tools/Cargo.toml --target-dir target --bin contract-search --bin extension-prescribe
python -B -m unittest tests.test_extension_design tests.test_extension_required_cells tests.test_extension_advance tests.test_extension_contract tests.test_extension_contract_assertions tests.test_extension_plan tests.test_extension_route tests.test_extension_explain tests.test_extension_scheduling
```

`verify.py` copies only contract metadata into `evidence/`, referencing unchanged
bank candidates and schedules. It compares individual Python/Rust results for
each of the standard 80 RNG/phase samples in each mode. It checks expected sample
counts as well as evaluator agreement; expected physical failures do not count
as verifier failures. `evidence/report.json` records the summary; each
`evidence/<fixture>/<mode>/` folder holds the generated contract, a compact
`cases.csv` (one row per sample), and the first failing driver trace. The full
per-case JSON with replay seeds and action orders (about 11 MB) is written to the
git-ignored `out/<fixture>/<mode>/cases.json` and regenerated by `verify.py`.

## Two distinct counterexamples

The real n4_14 mechanism passes both batch modes but fails interleaved scheduling.
At RNG 0, phases (0,0), tick 14, supplied input (15,0,3) discovers 17 sources
against cap 16. `tests/test_extension_scheduling.py` checks both endpoint passes,
the structured failure, and deterministic replay. This is a supplied-input-order
counterexample; there are no natural piston actions around its failing event.
Do not describe it as a strict natural-A/input/natural-B failure.

A separate tiny simulator regression demonstrates that strict intermediate gap:
`interleaved_natural_intermediate_load_failure_is_between_successful_endpoints`
in `src/sim.rs`. A finishes moving a stone, making it stationary next to a supplied
slime input; B subsequently starts moving the stone away. The input alone costs
one block before A or after B, but recruits the stone between their visits and
exceeds its cap of one. The same sample succeeds in both batch modes and fails
with load two only in the witnessed A/input/B order. This is a local scheduling
regression, not a recurring extension solution.

The bounded bank investigation and its scripts remain in `witness_trial/`.
Its statement that no strict witness was found applies to that bank probe;
the tiny simulator regression was constructed afterward.

## Feedback and remaining limits

Interleaved wrappers include a derived u64 `schedule_seed`; the original RNG and
chunk phases reproduce the run. Python failure replay includes per-tick seeds
and action coordinates. Rust failures include the sample, last traced tick's seed
and realized action order. A pre-action contact failure can therefore refer to
the preceding tick's replay, which is explicitly tick-labelled. Traces skip idle
piston visits, so the action list is not the entire visit schedule.

Prescribed starts and settlements are matched by input and movement identity,
including per-event load caps after reordering. Supplied passengers retain supplied
provenance. Tests retain the legacy ordering rules and verify deterministic
permutations, intermediate placement, empty-session equivalence, ownership,
movement/settlement timing and observer pulses.

The stress distribution uses random chunk buckets and random gaps within the
current shuffled piston lists, plus a tail bucket. It is not uniform over all
interleavings. Real-driver location, ownership and settlement timing still need
validation before an extension is called physically reusable. Next research work
is the frozen separate-output construction challenge in `../RESUME_TODO.md`.
